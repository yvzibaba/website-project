# V1 商业验证指标 · 最简记录方式（V1 冻结审计建 · 不开发 BI）

> 原则：**零新代码、零埋点、零 BI**。能从数据库精确取数的三项直接查表；页面级漏斗三项 V1 不做埋点，用「观察者人工计数」替代（与 `USER_VALIDATION_CHECKLIST.md` 六节 F1/F2 观察同源）。每批测试结束后由创始人或观察者花 2 分钟填表即可。

## 一、七项指标与取数方式

| # | 指标 | 口径 | V1 取数方式 | 精度 |
| --- | --- | --- | --- | --- |
| 1 | 访问方案人数 | 打开 /solutions 或 /solutions/[id] 的去重人数 | 人工计数（观察者记录每批到场人数 + 自发到方案页人数；F2 第一次点击落点） | 估算 |
| 2 | 进入沙盘人数 | 打开 /sandbox 的去重人数 | 人工计数（同上，沙盘入口点击即计） | 估算 |
| 3 | 运行沙盘人数 | 改参数后看到结果更新的去重人数 | 人工计数（观察清单指标 2「完成第一次运行」的通过人数即此数） | 估算 |
| 4 | 保存项目人数 | 当日新建 Project 且 ownerId 非空的去重用户 | **数据库精确**：后台 /admin/projects 列表行数，或 `Project` 表按 createdAt 当日计数 | 精确 |
| 5 | 询价人数 | 创建订单的去重买家（登录按 userId，游客按 buyerEmail） | **数据库精确**：/admin/orders 页可见；或 `Order` 表去重计数 | 精确 |
| 6 | 购买人数 | 同 5（当前闭环「询价即下单」：订单创建即购买意向，幂等去重） | **数据库精确**：同上（deduped 复用单不重复计人） | 精确 |
| 7 | 付款人数 | 订单状态 = PAID 的去重买家 | **数据库精确**：/admin/orders 中 PAID 行；或 `Order` 表 status=PAID 去重 | 精确 |

诚实边界：指标 1–3 在 V1 为人工估算，**不得对外引用为精确数据**；若后续需要精确漏斗，属 V1.1 BACKLOG（最小 pageview 计数），V1 明确不做。

## 三、与转化漏斗的对应

- 认知层（看懂）：到场人数 vs ①②之比 → 对应清单 F1/F2。
- 价值层（会用）：②③之比 → 对应清单指标 2。
- 留存层（认可）：③④之比 → 愿意留证据的用户。
- 商业层（掏钱）：④⑤⑥⑦逐级之比 → 对应清单 F5；任一环比骤降处记「卡点原话」列。

## 四、取数 SQL 备忘（可选，创始人自行执行时用）

```sql
-- ④保存项目（当日去重用户）
SELECT COUNT(DISTINCT "ownerId") FROM "Project" WHERE "createdAt"::date = CURRENT_DATE AND "ownerId" IS NOT NULL;
-- ⑤⑥询价/购买（累计去重买家）
SELECT COUNT(DISTINCT COALESCE("userId"::text, "buyerEmail")) FROM "Order";
-- ⑦付款（累计去重买家）
SELECT COUNT(DISTINCT COALESCE("userId"::text, "buyerEmail")) FROM "Order" WHERE status = 'PAID';
```
