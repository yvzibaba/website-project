**为什么这件事重要**：

`V2_FINAL_PRODUCT_MAP.md` §5 的强制原则 **P6 规定「产品文案禁止出现『沙盘』」**。
但命名不是文案——**命名会渗透到 API 路径、错误信息、日志、埋点、类型名、测试名、文档里**。
只要 `sandbox-` 还在内核文件上，产品就**必然**在某些界面/报错/文档里露出「沙盘」这个词，定位就不干净。

**因此新增一条迁移要求（本文独有）**：

> **P-1 批次 · 内核重命名**：把 `sandbox-*` 全前缀系统性重命名为域命名
> （例：`sandbox-model` → `pipeline-model`；`sandbox-storage-value` → `storage-value`；`sandbox-region-facts` → `region-facts`）。
> 这是**纯机械、可守卫、零行为变更**的改动（内核守卫会立刻验证），**必须做，且越早越好**——因为改名成本随时间线性上升。

## 2. 四个点名结构的最终判断

### 2.1 旧 `sandbox-model` 是否彻底退出 V2？

**答：作为「唯一生产引擎」——彻底退出。作为「位置与载体」——保留，原地重写。**

这个区分很关键，因为「淘汰 sandbox-model」这句话有两种读法，而它们导致完全相反的行动：

| 读法 | 行动 | 是否正确 |
|---|---|---|
| 「把 `kernel/src/server/sandbox-model.ts` 这个文件删掉」 | 删除 → **内核出现空洞** | ❌ **错** |
| 「它承载的**模型定义**与**唯一生产引擎**地位，必须被替换」 | 原地替换内容 → 保留位置与守卫 | ✅ **对** |

**为什么不能删文件**：

1. 它是 41 个内核文件中**最大的领域文件**（29,310 字节），是**唯一生产计算链的物质载体**；
2. 它**已通过内核守卫**（零框架依赖 / 无反向引用 / 白名单外依赖 0 个）。这份「干净」是**资产**，扔掉等于把已有的干净性作废；
3. `V2_FINAL_BASE_ARCHITECTURE.md` §3.3 已裁决：**底座 B 的形态就是「内核里的 TypeScript 模块」，不引入第二语言运行时**。因此能源计算的重写**只能发生在内核里**——也就是**这个位置**。

**同时必须承认它有三重结构性缺陷**（上一轮已定位，本轮不重复论证）：
参数单点化 / 场景边界不足 / 投资项系统性偏高。

**因此最终判定**：

| 项 | 判定 |
|---|---|
| 旧模型的**参数架构**（单点化、50 参数硬编码） | ❌ **淘汰**（迁到结构化基准层） |
| 旧模型的**场景边界**（不足） | ❌ **淘汰**（重设计为「场景层」） |
| 旧模型的**投资项口径**（系统性偏高） | ❌ **淘汰**（口径重做） |
| 旧模型的**文件位置与框架无关性** | ✅ **保留** |
| 旧模型的**命名 `sandbox-model`** | ⚠️ **必须改名**（P-1 批次） |

> **一句话**：**换的是「里面装什么」，不是「这个盒子存不存在」。**

### 2.2 旧 Sandbox UI 是否彻底退出 V2？

**答：是，彻底退出。这是本文最明确的一条否决。**

| 维度 | 旧 Sandbox UI | V2 决策平台 UI |
|---|---|---|
| 交互范式 | 用户**自己调参数**，看数字变化 | 用户**填条件**，系统**给推荐 + 理由** |
| 定位暗示 | 「玩」（沙盘） | 「做决定」（平台） |
| 是否有推荐 | ❌ 无（用户自己试） | ✅ **推荐是灵魂**（产品地图 §2.2） |
| 是否有证据溯源 | ❌ 弱 | ✅ 每个数字可点开（P2） |
| 输出 | 屏幕上的数字 | 可交付第三方的**决策报告**（P7） |
| 与收费点的关系 | 「好玩」→ 付费意愿 0 | 「要担责」→ 付费意愿高 |

**淘汰的四条理由**：

1. **定位冲突（最根本）**：沙盘的交互范式**在物理上就是**「随意试验」，而 V2 的定位是「为决策负责」。**不是同一产品**。
2. **规模确实很大但价值密度低**：128,933 字节 / 12 文件，是**第二大**旧产品面，但它输出的是「数字」而不是「结论 + 理由 + 证据」。**保留它等于保留一个与收费点无关的巨型模块。**
3. **它承载了「页面级计算」这个反模式**：淘汰它同时消灭了淘汰清单 #8（页面级计算）。
4. **它暴露了参数堆积**：参数的堆积正是**通过这个 UI** 暴露给用户的（上一轮方案已指出）。UI 不淘汰，参数架构就改不动。

**处置方式**：

| 动作 | 说明 |
|---|---|
| **不在 V2 产品面出现** | V2 无 `/sandbox` 路由 |
| **退役而非隐藏** | 不保留「隐藏入口」——隐藏会让新旧两条路径并存于代码 |
| **能力拆解回收** | 图表（`SandboxCharts`）→ M3 项目工作台复用；面板（Explain/Report）→ M8 决策报告复用；其余（Workbench/Shell/Save/Upgrade/Demo）→ 退役 |
| **顺序**：先冻结 → 新 UI 跑通 → 再删** | 不立即删（避免孤儿引用），标注 deprecated |
| **`/ui` 组件演示页** | `src/app/ui`（10,083）保留（开发用），但须移除所有沙盘相关演示 |

### 2.3 旧案例 / 方案首页是否彻底退出 V2？

**答：作为「对外产品面」——彻底退出。作为「资产」——降级为上游证据（保留，且这是 V1 最被低估的资产）。**

这与战略定稿 Q8 的裁决完全一致：

> **案例从「货架上的商品」变成「工厂里的原料」。**

| 项 | 退出 | 保留 |
|---|---|---|
| `src/app/cases` + `cases/[id]`（29,611） | ❌ **退出**（不再有对外案例浏览页） | — |
| `src/app/solutions` + `solutions/[id]`（39,664） | ❌ **退出**（「可售卖报告」语义属 V1） | — |
| `components/industries` `components/solutions` | ❌ **退出** | — |
| `Case` `Evidence` `BusinessModel` `TechCapability` `CaseCapability` model | — | ✅ **保留 → 上游 M1 知识底座** |
| `scout*` / `research-pipeline` / `scoring` / `case-scores` | — | ✅ **保留 → 上游引擎的内部流水线** |
| `Region` `Market` `Localization` / `Supplier` | — | ✅ **保留 → 本土化输入 + L5 供给侧种子** |

**为什么必须退出（而不仅仅是「降级显示」）**：

1. **V1 的 L2 是「卖报告」，V2 的 L2 是「卖决策包 + 服务单」。** 案例/方案页面承载的是 V1 的商业模型代码路径（`SolutionFinancial` 的售卖语义、下单、支付凭证）。**商业模式已变，这条链路必须断开**。
2. **上一轮方案的三条硬边界之一**：`V1 商业模式代码不得被 V2 复用`。案例/方案页面正是这条边界的**边界物**——不淘汰它们，边界就只是一句声明。
3. **它们的内容形态会被 V2 取代**：V2 对外呈现证据的地点是**决策报告里的「来源引用」与上游机会页**，不是一个独立的案例库。

### 2.4 旧六行业展示结构是否彻底退出 V2？

**答：是，彻底退出。**

| 项 | 判定 |
|---|---|
| `src/app/industries`、`industries/[slug]`、`components/industries/*`（15,592） | ❌ **淘汰** |
| `src/server/industries.ts`（6,122） | ❌ **淘汰**（能力并入上游 M1） |
| 「行业切换」的**能力**（换行业只换最后一层） | ✅ **保留在设计里**（架构分层） |

**三条理由**：

1. **违反「极度聚焦」**：V2 第一旗舰是**单一行业深做**（新能源重卡光储充）。**六行业并列展示是 V1 的「广度叙事」**，与 V2 的「深度决策」正面冲突。一个用户看到「我们支持六个行业」只会得出「什么都不精」的结论。
2. **它把「行业」错误地做成了产品导航**：正确的做法是**行业在配置里，不在导航里**。第二层换行业 = 换行业模型，前两层原样复用——这是**架构能力**，不需要产品面展示。
3. **它占位了一个不该占的位置**：`industries` 是上游层（机会发现）的产出形态，把它做成对外导航，等于**把内部流水线暴露成产品**。

### 2.5 四个判断的汇总（一表）

| 点名结构 | 彻底退出 V2？ | 关键处置 |
|---|---|---|
| **旧 `sandbox-model`（作为生产引擎）** | ✅ **是**（引擎地位退出） | ❌ 删除文件？**否** —— **原地重写内容 + 改名**（盒子留下，内容换掉） |
| **旧 Sandbox UI** | ✅ **是** | 不保留路由、不保留隐藏入口；能力拆解回收（Charts→M3、Report→M8）；先冻结后删 |
| **旧案例 / 方案首页** | ✅ **是**（对外产品面退出） | 页面淘汰；**数据与评分能力迁移到上游 M1**（从商品变原料） |
| **旧六行业展示结构** | ✅ **是** | 页面与服务淘汰；**行业切换能力保留在架构分层里** |

> **四条全部退出。** 但要注意一个重要的**不对称**：
> **「退出」= 退出产品面与生产路径，≠ 一律删除数据与能力。**
> 唯一一条连能力一起废弃的是 **Sandbox UI**；其余三条都是「页面退、能力留（换位置）」。
