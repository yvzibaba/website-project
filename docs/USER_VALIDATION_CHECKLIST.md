# 真实用户验证清单（User Validation Checklist · 阶段3A）

> 目的：为第一批真实用户试用做最简验证准备。**不开发复杂反馈系统**——本清单打印或复制到表格即可使用，每用户一份。
> 产品入口：`/sandbox`（示范项目模型，约 10 参数简化入口；需要时可展开完整 40 参数工作台）。
> 诚实前提（须在开场告知用户）：沙盘默认数字均为**占位假设（未经逐条核实）**，经济口径为透明简化，结果**需专业人工确认**，不得作为投资/并网决策依据；山西已核实政策条款可在页面「已核实政策条款 · FACT」区点击溯源，但**条款≠沙盘数值**。

## 一、用户类型与前置条件

| 编号 | 用户类型 | 参考画像（对应回归场景） | 前置准备 |
| --- | --- | --- | --- |
| U-S | 小型车队 | 约 20 辆重卡、光储初配（对应回归场景 small） | 可上网电脑/平板；无需注册即可浏览，运行不依赖登录 |
| U-M | 中型车队 | 约 60 辆重卡、光储标配（对应回归场景 medium） | 同上；如测「保存/导出/询价」链路需临时测试账号 |
| U-L | 大型车队 | 约 150 辆重卡、可谈电价（对应回归场景 large） | 同上；建议由熟悉采购流程的人员参加 |

开场话术（照读）：「请在沙盘里像给自己公司做决策一样操作：选地区→改参数→运行→看结果。全程不指导，只观察和记录。」

## 二、八项观察指标（每人一份，逐项勾选）

| # | 指标 | 观察方式 | 记录（通过/不通过 + 原话摘录） |
| --- | --- | --- | --- |
| 1 | 理解参数 | 不解释，看用户能否说出电价/里程/储能等输入是什么意思 | |
| 2 | 完成第一次运行 | 用户能否独立完成：选地区→改参数→看到结果更新（无卡顿/报错） | |
| 3 | 最常修改参数 | 观察整个过程中用户反复调整的 1–3 个参数（开放记录） | |
| 4 | 最关心结果 | 记录用户停留最久/主动追问的结果指标（开放记录） | |
| 5 | 最不可信结果 | 直接问「哪个数字你最不信？」，记下指标与原因（开放记录） | |
| 6 | 理解储能价值 | 用户能否复述「储能在这里怎么赚钱」（削峰填谷/价差套利） | |
| 7 | 理解 IRR 与 Payback | 用户能否用自己的话说出 IRR 和回收期的区别与含义 | |
| 8 | 愿意询价购买 | 看完结果后是否愿意点击询价/购买入口（或明确说出不会及原因） | |

## 三、标准任务脚本（≈15 分钟，供观察者对照）

1. 打开 `/sandbox`，选择地区「山西」。
2. 按自己公司情况修改核心参数（车队规模/里程/电价/光伏/储能）。
3. 运行并查看：CAPEX（净/毛）、OPEX、首年收入、NPV、IRR、ROI、回收期。
4. 打开敏感性（龙卷风图），找出对结果影响最大的参数。
5. 生成动态报告并通读；点击「已核实政策条款 · FACT」区的原文链接。
6. （有账号时）保存项目 → 导出产业方案 → 查看方案详情页的购买/询价入口。

## 四、判定与汇总（观察者填，每批 3 用户收齐后汇总）

- 指标 1/2/6/7/8：按「用户独立完成且说对」判通过；指标 3/4/5 为开放记录，不判通过。
- 单用户结论：8 项中判分项 ≥4 项通过 →「可邀请扩大试用」；否则记录阻塞原因。
- P0/P1 分级：凡导致任务 2 无法完成的缺陷记 **P0**；导致报告/询价链路无法走通的记 **P1**；其余为改进项。
- 汇总三问（供创始人决策）：① 三类用户最常修改的参数是否一致？② 最不可信的结果集中在哪几个数字？③ 有没有人走到询价一步、卡在哪？

## 五、与阶段3A 回归场景的关系

本清单用户画像与 `tests/fixtures/regression/scenarios-sml.json` 三组场景（small/medium/large）一一对应：用户实测前可先跑对应场景确认基线结果在位（模型回归绿），确保用户看到的产品行为与开发者验证的是同一份。
