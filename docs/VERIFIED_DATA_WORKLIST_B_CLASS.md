## 0. 为什么先做 B 类

> L1 基准的可信度主要压在 B 类这 41 个上。A 类做的是「同一套方法在不同省的落地」，
> B 类做的才是「这套方法本身站不站得住」。只做 A 不做 B，得到的是「一个算得很快但没人信的沙盘」。

当前 **50/50 全部 `evidenceKind=ASSUMPTION`、`confidence≤50`** —— 结构完整、数据空心。
本作业单的任务是把这 41 项**逐项变成可追溯来源**。

**分母核对（与 `04-DATA-PROVENANCE.md` §4.4 逐一对齐）**：
`region.*`(5) + `policy.*`(4) = **A 类 9**；`project.*`(16) + `technology.*`(18) + `finance.*`(7) = **B 类 41**。合计 50 ✓

## 1. 先做一次诚实分类修正：41 项里只有 29 项真需要外部证据

把 41 项**一股脑当作「要去找行业资料」会导致大量无用功**。按「证据形态」拆开：

| 子类 | 数量 | 需要的是什么 | 为什么要分开 |
|---|---:|---|---|
| **B0 · 派生值** | **3** | **不需要外部证据** —— 需要的是公式正确性复核 | 它们由其它参数算出，外部不存在「来源」。**当前 `source` 文案把它们写成「占位假设·待核实」，属于误导**（见 §4） |
| **B1 · 场景输入** | **9** | **需要客户/设计方案给定**，不是行业共识 | 同一个场站换客户就变（车流、装机、桩数、是否配储）；找"行业平均值"当来源反而是错误的取证方向 |
| **B2 · 真需行业证据** | **29** | **行业共识 / 国标行标 / 设备厂手册 / 上市公司披露 / 招投标公示** | 不随省变，也不随客户变 —— **这才是"这套方法站不站得住"的真正承重墙** |

> **3 + 9 + 29 = 41** ✓　**真正待取证的是 29 项，不是 41 项。** 这个修正本身就是省下的无用功。

## 2. 取证来源分级（S1–S5）

| 级别 | 来源类型 | 例 | 可否单独作为 FACT |
|---|---|---|---|
| **S1** | 国家标准 / 行业标准 | GB/T、NB/T、DL/T | ✅ 可直接 FACT |
| **S2** | 政府 / 法定机构公开文件与统计 | 国家能源局、发改委、央行、统计局 | ✅ 可直接 FACT |
| **S3** | 行业协会 / 权威研究机构 | 中国光伏行业协会（CPIA）、中关村储能产业技术联盟（CNESA） | ✅ 可 FACT（须标机构与发布日期） |
| **S4** | 招投标中标公示 / 上市公司披露 | 公共资源交易平台、巨潮资讯 | ✅ 可 FACT（**须为具体项目、可点开**） |
| **S5** | 券商研报 / 咨询机构 / 媒体转述 | 各类行业报告、财经媒体 | ⚠️ **只能交叉印证，不得单独作唯一来源** |

**验收标准（每项都要满足）**：
1. 来源可点开核验（有 URL，且指向具体页而非首页）；
2. 记录 `asOf`（该数值的时点）——**成本类数值时效性极强，2024 年的造价不能标注为 2026 年基准**；
3. 写明 `sourceType`，并落到 S1–S5 之一；
4. 给出区间而非单点（造价类参数必须给样本区间与中位）；
5. `confidence` 按「来源级别 + 样本数 + 时效」三因子给，**不得因为"看起来合理"而给高分**（宪法 §34）。

### 3.0 B0 · 派生值（3 项）—— 不需要行业证据

| 键 | 定义 | 要做的不是取证，而是 |
|---|---|---|
| `derived.dailyChargeEnergy` | = 车数 × 单车电量 | 复核公式与量纲（辆/日 × kWh/车·次 = kWh/日） |
| `derived.chargerTotalPower` | = 桩数 × 单桩功率 | 同上（台 × kW = kW） |
| `derived.storageDuration` | = 容量 ÷ 功率 | 同上（kWh ÷ kW = h）；且 **1.5.0 已把名实修正为「储能满功率放电时长」** |

**动作**：把这三项的 `source` 文案从「【占位假设·待核实】…须逐项替换为可追溯来源」改为
「【派生值】由 A/B 类参数计算得出，无可外部核验的独立来源；正确性由 `SANDBOX_DERIVED` 公式复核保证」。
**这是一项诚实性缺陷**：现在读起来像是"还没找到来源"，实际是"这类参数本来就没有来源"。

## 4. 一项诚实性缺陷（必须修）

3 个派生参数的 `source` 文案与其余 38 项**完全相同**：
「【占位假设·待核实】V1 取行业常见量级跑通链路，非经核事实，须逐项替换为可追溯来源」。

**问题**：派生值**不存在**「可追溯的外部来源」，它由公式决定。这句文案会让人以为"再去找找就有了"，
从而把 3 项**永远不会被满足**的任务长期挂在欠功课清单里 —— 这正是 §34 要防的「用模糊口径掩盖真实边界」。

**建议**：单独为 `derived.*` 写一组文案（见 §3.0），并在 `04-DATA-PROVENANCE.md` §4.4 的分母说明里加一句脚注：
「41 项含 3 个派生值，派生值不参与外部取证」。

## 6. 执行原则（防止把好意图做成坏工程）

1. **本轮不改任何参数值。** 只产出证据档案；改值单独立项、创始人批准、`CHANGELOG` 留痕。
2. **口径不一致不得硬套**（§5.2 就是例子：电网侧 100MWh 价格 ≠ 用户侧 400kWh 价格）。
3. **成本类必须带 `asOf`。** 光伏/储能造价年降幅 20%+，无时点的造价等于没有造价。
4. **S5 来源不得独家作证。** 媒体转述的数字必须回溯到原始出处。
5. **`confidence` 不得因"看起来合理"上调。** 判定依据只有三因子：来源级别、样本数、时效。
6. **允许"取证失败"并如实记录。** 找不到可靠来源时写「未找到 S1–S4 来源」，而不是拿一个 S5 数字充数（§34）。
