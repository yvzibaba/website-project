## 一、项目是什么

> **为新能源重卡光储充项目提供「可被第三方引用、可复算、可溯源」的项目决策平台。**

身份：**轻资产决策服务方与项目发起方**。不建项目、不持资产、不做投资决策、不做自动报价。

**产品定位的三条硬边界（写错任何一条产品就会走回 V1）：**

| 不是 | 是 |
|---|---|
| ❌ 沙盘 / 计算器 / 模拟器 | ✅ 项目决策平台 |
| ❌ 「拖着参数看数字变化」 | ✅ 「填条件 → 系统给出推荐 + 理由」 |
| ❌ 屏幕上的数字 | ✅ 可交付第三方的决策报告 + 实际数据回流 |

## 四、技术架构（唯一允许的形态）

```
① 产品层      src/app/**、src/components/**     页面与组件；零计算
② 领域内核    kernel/**（@app/kernel）            零框架依赖；可被依赖，绝不反向依赖
                ├─ engine/   ← V2 决策引擎（唯一生产计算引擎）
                ├─ server/   ← 服务与数据访问（含 V1 遗留）
                └─ lib/      ← 纯函数工具（含 V1 遗留）
③ 持久层      Prisma 6 + PostgreSQL（Neon）      Prisma 是唯一的表所有者
```

**三条边界铁律（不可协商）**

2. **不引入第二语言运行时**（禁 Python / Julia sidecar；能源方法一律 TS 重写）
3. **不 fork 任何外部项目**；不新增 AGPL/GPL 依赖

细则见 [`ai-rules/01-ARCHITECTURE.md`](ai-rules/01-ARCHITECTURE.md) 与 [`ai-rules/03-KERNEL.md`](ai-rules/03-KERNEL.md)。

## 五、八条强制设计原则（每条都可机械核验）

| # | 原则 | 核验方式 |
|---|---|---|
| **P1** | IA 以「项目」为中心，不以「计算」为中心 | 首页主 CTA 是否指向项目列表；项目是否是一等实体 |
| **P2** | 每个数字可点开看到来源 / 日期 / 置信度 | 界面是否暴露 `source` / `validFrom` / `confidence` |
| **P3** | 推荐必须给「理由」**和「为什么不推荐别的」** | 决策输出是否含 reasons + concerns + 对比依据 |
| **P4** | Actuals 采集位从第一天就存在 | 表 + 写入路径是否存在 |
| **P5** | 免费层必须给**结论倾向**，不能只给表单 | 是否存在免登录的诊断输出 |
| **P6** | 产品文案禁止「沙盘」「计算器」「模拟器」 | 全仓检索用户可见字符串 |
| **P7** | 决策报告必须内置「下一步找谁」出口 | 报告章节是否含落地出口 |
| **P8** | 模型必须同时容纳充电与换电两条技术路线 | 两条链是否都有建模与测试 |

## 七、绝对约束（不可协商）

1. **只有一台生产计算引擎。** 界面、API、报告、推荐全部调用同一个 `runCalculation()`。
   **禁止为"预览""推荐""诊断"另写轻量算法**——那会直接制造「页面上的数 ≠ 存下来的数」。
2. **内核不许依赖框架。** 每次改内核后必须跑 `kernel:verify`，0 违规才算完成。
3. **禁止把未知当已知。** `UNKNOWN` 不得用 0 或行业均值顶替；`FACT` 必须有合法 http(s) 来源链接。
4. **禁止编造来源。** 宁可维持 `ASSUMPTION`，绝不为凑「已核实」而填链接。
5. **禁止虚构完成 / 虚构测试通过 / 隐藏错误。** 验证结果必须附真实输出。
6. **关键计算必须由程序完成**，禁止 LLM 口算（宪法 §7）。决策解释必须是程序生成、可追溯。
7. **改引擎必须先冻结基线。** 改完若黄金值变化，必须逐条解释原因，不得直接改测试常量。
8. **中文文案可改，英文标识符与持久化字面量不可改。**
   保护清单（值永久不变）：`sandboxSource` · `sandbox-solution@` · `sandbox-solution-provenance@` ·
   `sandbox-solution-source@` · `sandbox-scenario` · `sandbox:explain` · `SANDBOX_ENTITLEMENT_*` ·
   迁移目录名 `20260905140000_add_sandbox_project`。
9. **不达批次出口条件不得跳批次。** 若创始人要求跳，必须明确指出风险并说明代价。
10. **禁止未经允许删除已有功能。**
11. **定价、多租户形态、服务交付流程需创始人裁决**——不得擅自决定。

## 八、每次开工的动作

```
1. READ   → 宪法 + 商业模式 + 产品地图 + 术语表 + 本文件；确认当前批次
2. PLAN   → 声明：① 属于 L1/L2/L3/L4 哪层 ② 解决获客/留存/付费/数据质量/交付质量哪个
            ③ 会碰内核吗 ④ 会不会改变黄金基线
3. ACT    → 最小化改动；同一文件的多处修改必须串行（并行会静默覆盖）
4. VERIFY → 跑第 3 节基线并附真实输出（见第九节模式）
5. DOC    → 更新文档 + CHANGELOG（版本号·时间·原因·内容·效果）
6. REPORT → 用零基础能懂的话说清：完成了什么 / 现在能做什么 / 还剩什么 / 有什么风险
```

**PLAN 阶段答不出「属于哪层」和「解决什么」→ 不要开工。**

## 九、验证模式（本机实测有效，照抄）

```bash
# 快速门（每批必跑，秒级）
npm run typecheck && npm run kernel:typecheck && npm run lint && npm run kernel:verify && npm run kernel:dangling

# 单测（秒级）
npm run test:unit

# 构建：必须带前缀，否则收尾清理 .next 会撞本机删除守卫（是假失败）
CODEBUDDY_SAFE_DELETE_ENABLED=0 npm run build

# 集成（跨境连 Neon，约 12.5 分钟，后台跑，改动过内核要重跑）
npm run test:integration
```

**判据与坑**

| 现象 | 真相 |
|---|---|
| `build` 报 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]`，但日志已有 `Compiled successfully` | **构建实质成功**，只是收尾清理被拦。**不要据此改代码** |
| `test:integration` 用 `2>&1 \| tail -N` 全程无输出 | `tail` 只在 EOF 输出，不是卡死。用 TCP 探 5432 可先证网络可达 |
| `migration_lock.toml` 长期显示已修改 | 本机 `core.autocrlf` 换行符归一化副作用，`git diff` 为空，无害 |
| 推 GitHub 失败 | 走 `bash ~/.workbuddy/skills/github-via-ghelper/scripts/ghproxy.sh git push origin rewrite-v2` |
