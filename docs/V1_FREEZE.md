## OPEN（V1 测试前必须完成）

1. 创始人亲自过一遍 10 个测试场景（上一阶段报告清单），确认无体感阻塞。
2. 确定第一批邀请用户名单与批次（建议 3–5 人，对应清单 U-S/U-M/U-L 三画像）。
3. 确定测试环境：localhost 预览（当前）或部署到公网临时域名——若公网，先读 HUMAN INPUT 第 2/3 条。
4. 付款说明页文案终审（当前为人工转账说明，须与实际收款方式一致后才发用户）。

## BACKLOG（V1.1 记录在案，V1 期一律不实施）

1. `/api/feedback` 无验证码/限流（已有 CSRF+长度限制；公网开放后需防滥发）。
2. `/admin/users`、`/admin/projects`、`/admin/orders` 只读页无分页（上限 200/100 条）。
3. `package-lock.json` 远端漂移未推（新 clone 需 `npm install` 重建）。
4. 页面级精确漏斗埋点（最小 pageview 计数），替代 `V1_METRICS.md` 中三项人工估算。
5. 弱网首屏 loading 体验优化（loading.tsx 因软 404/307 契约被禁用，需更细粒度方案）。
6. smoke/审计脚本夹具登记 + afterAll 零残留自检（本次审计发现 2 条夹具案例漏清的教训）。
7. 邮箱验证流程（`emailVerified` 当前注册即可用，未验证邮箱）。
8. 移动端细节打磨（沙盘滑杆与长表格在窄屏的可用性）。

## HUMAN INPUT（必须创始人决定）

1. **方案定价**：沙盘导出方案为 DRAFT，需人工替换数据并定价后才可对外售卖（当前唯一业务级缺口）。
2. **真实收款信息**：付款说明、收款账户、开票口径——涉及法律合规，AI 不代填。
3. **隐私政策/服务条款**：当前为占位草稿（页脚已明示），需法务审定后生效。
4. **生产部署与域名**：是否部署公网、部署到哪、密钥/环境变量管理方式。
5. **真实政策数据计划**：G1–G10 缺口（平段基价、需量电价等）的采购/核实路线，AI 禁止编造。
6. **第一批用户名单**与是否签署简单测试协议。
