## 3. 加载顺序（每次任务开工前）

```
1. 宪法 V2.0（重点 §3 功能归属 / §7 关键数字 / §20 不许虚构 / §24 闭环稳定 / §27 冲突裁决）
2. 商业模式定稿（确认你要做的功能属于 L1 / L2 / L3 哪一层）
3. 总控 Prompt V2.0（当前 Phase 与允许范围）
4. 本目录涉及的分册：
   - 动到计算逻辑        → 03-KERNEL
   - 动到数据/参数/来源  → 04-DATA-PROVENANCE
   - 动到内容/后台       → 02-PAYLOAD
   - 任何改动            → 01-ARCHITECTURE + 05-TESTING + 06-DELIVERY
```

## 4. 三条永久禁令（跨分册，最高频违规）

1. **禁止自研已被解决的问题。** 账号、权限、计费、后台、审计 —— 一律用成熟方案或已有实现，不新写。
2. **禁止让领域内核依赖框架。** `@app/kernel` 不得出现 `next` / `react` / 浏览器 API / `next-auth`。
3. **禁止把占位数据当事实输出。** `confidence≤50` 或 `evidenceKind="ASSUMPTION"` 的值，不得进入对外发布的算例与结论。

## 5. 本目录的维护规则

- 分册内容变更须走 Git 提交，重大变更记入 `../CHANGELOG.md`（版本号 + 时间 + 原因 + 内容 + 效果）。
- 新增分册须同步更新本索引第 2、3 节。
- **禁止在本目录写与宪法冲突的规则。** 若发现宪法本身需要改，走 §29–§34 那种增补提案流程，不得在分册里绕过。
