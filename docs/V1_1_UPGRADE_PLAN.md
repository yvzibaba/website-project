## 0. 一句话结论

当前平台是一台**引擎真实、外壳失真**的技术 Demo：计算内核（R0–R9 全链、黄金样本、溯源脊柱、权限、订单状态机）质量很高，但**外围呈现层对用户撒了三个弥天大谎**——① 车队规模不带动设备配置（20 车和 150 车用同一套 8 桩 CAPEX）；② 需量电价主情景与已核实的 2030 前免征政策冲突（把该收 0 元的费用算成压垮小型项目的负 NPV）；③ 融资/土地/碳价/并网容量等参数摆在用户面前假装在算、实际全不参与计算（僵尸参数）。V1.1 的使命：**不重写引擎，只把"假"的地方修成真、把"黑话"翻成人话、把"断裂的购买路径"接上**，让陌生企业用户 30 秒理解、5 分钟测算、20 分钟拿到方案、愿意留资。

### 1.2 各层审计摘要

**计算引擎层**：车辆→年里程→百公里电耗→日充电量→桩功率/桩数→总装机→峰值负荷→并网容量→计费需量→电费→NPV 的因果链上，**"桩数"与"并网容量"两环断裂**：`project.chargerCount` 恒定默认 8（demo 路径永不随车队缩放，`demo-project.ts:272-303`）；`project.gridCapacity`（2000kW）全模型零消费（僵尸）。计费需量 = 装机×平均利用率（口径 A），概念上是"平均"冒充"最大"，且主情景 40/44 元与"2030 年前集中式充换电免需量电费"的已核实政策直接冲突。财务侧 equityRatio/loanRate/landRent/carbonPrice 全部声明但零参与——**所有回报指标实为全投资口径，却未向用户言明**。

**持久层**：JSONB paramLayers 设计优秀（新参数零 schema 迁移即可回放）；但重开历史项目用**现行引擎**重算（无引擎版本钉），存在"昨天的项目今天数字变了"的静默漂移隐患，现仅靠写时冻结缓解。

**UX 层**：首页仍是"产业案例内容平台"人设（品牌"产业案例引擎"、V1-A 徽标、60→20→10→3→1 流水线漏斗文案）；沙盘与报告暴露大量内部黑话（MODEL_VERSION 页脚、"占位假设"徽标、E1–E8、Δ_sto、S1-gap、`?demo=1` 泄漏进空态文案）；企业页承诺"询价"但全站**无留资表单**；沙盘导出方案的端点挂 `requireStaffWrite`（**买家自己导出自己的方案要 staff 权限**，商业闭环在最后一米断开）；收款/客服信息为未配置占位符。

**测试基建**：单元 1081 + 集成全绿，但**零 UI/E2E/API 路由测试**；黄金重录脚本 `sml-regen` 不在仓库（重录靠临时脚本，属丢失的工程资产）；敏感性假联动守护测试（`causality.test.ts` L331-343）把僵尸参数**钉为已知假联动**——接线时须同步改写，这是现成的施工图。

## 3. 设计决策（对应创始人指令的第二~六阶段）

### 3.1 沙盘可信度修复（P1 核心）

#### (a) 车辆规模 → 能源需求 → 设备配置 链路（批次 1，改映射层不改引擎）

在 `demo-project.ts::demoUserValues` 内建立完整传导：

```
日充电量      = trucksPerDay × chargePerTruck                     （已有）
建议桩数      = ceil( 日充电量 / (chargerUnitPower × T小时) )       （新增，T=补能窗口，默认 6h，入参可见）
总装机        = 建议桩数 × chargerUnitPower                        （引擎已有派生，随桩数自动变）
日充电能力    = 建议桩数 × chargerUnitPower × T                     （随链路自动变）
CAPEX/E2运维/需量基准                                        （引擎已消费 chargerCount/chargerTotalPower，随链路自动变）
```

- 用户改卡车数/里程/电耗/单桩功率 → 桩数、总装机、CAPEX、峰值、电费、NPV 全链联动。
- 补能窗口 T 作为 Level-1 第 10 个核心输入（同时覆盖"同时率"语义：需要的桩数 vs 车位数之比即隐含同时率）。
- **约束告警（只提示不改数）**：若 `建议桩数 × 单桩功率 × 峰值系数 > gridCapacity 默认值`，在结果区出「按此时段集中补能将超过常规报装容量，建议错峰或增容」的**人话告警卡**——把 #6 的硬伤从"隐性错"变成"显性提示"。
- MODEL_VERSION **刻意不升**（引擎公式一字不动，只是输入不再是常数 8）；黄金基线（demo 默认 60 车标态）经标定复现现值或**有意重录并逐条写明原因**。

#### (b) 充电负荷模型六要素

在 Level-2 工程模式明示、Level-1 只暴露其中 2 项（单桩功率、补能窗口）：单车电量、单桩功率、日需能量、补能窗口 T、同时率（=建议桩数隐含）、最大功率（=桩数×功率×需用系数 Kc）。V1 采用**需用系数 Kc（默认 0.7，可调）**作为"平均"与"最大"之间的桥，不再用平均利用率冒充最大需量。

#### (c) 需量电价 A/B/C 三场景（批次 2，升 MODEL_VERSION → 1.3.0）

| 场景 | 计费需量基准 | 需量单价 | 语义 |
|---|---|---|---|
| **A 政策优惠（新主情景）** | — | **0** | 2030 前实行两部制电价的经营性集中式充换电设施免收需量(容量)电费（已核实：山西发改委+全国监管周期条款），带 sourceUrl 挂 FACT 或强标注 |
| B 普通工商业 | 装机 × Kc | 44（山西）/40（全国） | 免征适用性存疑项目的**保守对照组** |
| C 保守高成本 | 报装容量（=装机全额） | 44/40 | 压力测试上界 |

公式改动：`billedDemandKw = chargerTotalPower × demandKc/100`（Kc 取代 chargerUtilization 承担此职责，chargerUtilization 回归"利用率"本义仅用于能量侧）；`region.demandCharge` 主情景默认 0 + 政策说明 note；场景切换 = 参数覆写而非新代码分支。**黄金有意重录**：基线 NPV 回升（需量费归零）、S 情景预期转正、B/C 作为对照锚点焊进回归（demandCharge=0 交叉焊点已存在）。敏感性扫描集把 demandKc 加入、语义修正 chargerUtilization。`MODEL_AUDIT` 的 F-2a/F-2c 相关守护测试同步改写。

#### (d) 投资模型完善（批次 3 呈现 + P5 真融资腿）

- **立即可做（P1 批次 3）**：报告与结果卡明示「当前全部回报指标为**全投资口径（无杠杆）**」；僵尸参数（equityRatio/loanRate/landRent/carbonPrice/gridCapacity）在 Level-2 收起至「未启用·即将支持」分组并注明原因，**不再假装在算**（信任速赢）。
- **V1 简化融资腿设计（P5 执行，须先获人工决策）**：贷款比例 D（默认 70%）、年利率 r（默认待定——**禁止编造，需创始人/银行侧给数**）、等额本息 N 年、宽限期 0；新增输出：债务现金流、还本付息计划、**DSCR=min(年偿债覆盖)**、**资本金 IRR/NPV**、电价与利用率风险双压测（DSCR<1 的临界电价/利用率）。`MODEL_VERSION → 1.4.0`，CalcResult 加可选 `finance?` 子对象（不并入现有字段，透明单列，沿用 demandChargeY1 的"独立字段"先例）。

### 3.2 产品定位重构（P3，纯呈现层）

- 一句话定位对外统一为：**「新能源重卡光储充项目的投资决策软件——3 分钟算清投多少、几年回本、最怕什么」**。
- **首页三屏**：① 价值句 + 「免费算一个项目」按钮（直达 Level-1 沙盘）；② 三个真实商业问题卡（"这个场站值不值得建？" "银行会看什么指标？" "哪个变量最影响回本？"各配一个沙盘截图式结果示例·标注示意数据）；③ 「案例结果」区（诚实空态："真实案例验证中，首批用户将获得企业适配"，**不编造**）。
- 品牌文案从"产业案例引擎"→"光储充投资决策沙盘"（`layout.tsx` metadata 同步）；删除/翻译全部内部名：V1-A 徽标、MODEL_VERSION 页脚、E1–E8/Δ_sto/S1-gap、`?demo=1`、"占位假设"改为面向用户的"示例参数·待核实"（且只在悬浮说明出现，不糊卡片）。**白名单清单见 Phase 3 表**。

### 3.3 商业模式三层级（P4）

| 层级 | 内容 | 权限 |
|---|---|---|
| 免费·获客 | Level-1（10 参数）+ 即时报告（带声明） | 无需登录 |
| Pro·收费企业工具 | Level-2 全参数 + 敏感性 + AI 解释 + 多项目/多情景/版本回滚 + 导出方案 | 登录（V1.1 先全开，计费开关留桩） |

- 一次性买断**降级为**"单份方案购买"（既有 Solution+Order 闭环保留为主转化物，不作为软件主模式）；私有化部署列高级方案（只挂留资，不做实现）。
- **买家导出闭环修复**：`POST /api/workbench/solution` 从 requireStaffWrite 改为「登录用户 + 项目属主」语义（服务端现算不变、DRAFT 状态不变、定价仍由 staff 后台完成后才进入购买），端点权限变更列人工决策项。
- **留资（RFQ）**：新建轻量 `Lead` 落库（复用既有 JSONB 表扩展或新表迁移 additive）+ `/api/leads` 受频控公开端点 + 企业页/报告尾/定价位三处「申请企业版报价」表单（公司/角色/项目阶段/预算区间/联系方式）。提交后诚实告知"1 个工作日内人工联系"。

### 3.4 UX 两条路径（P3+P4 穿插）

游客路径：首页→免费沙盘→拖滑块→结果+一句人话结论→生成报告（水印声明）→「保存需注册」→注册。企业路径：登录→画像→Level-2 精调→导出方案→（Phase 4 修复后可自助完成）→留资/下单。每步断点在 Phase 4 后用 E2E 冒烟脚本验证（见 P6）。

### 3.5 AI 投资顾问（P7）

不新造聊天机器人。把现有 `decision-explain.ts`（已实证 LLM 逐字引用报告数字、what-if 全定性）**升级包装为「投资顾问解读」**：输入仍是确定性报告全文 + CalcResult 摘要；输出增加「三段式」固定结构——能不能投（阈值判断：NPV>0 且 IRR>资本金成本参考线时表述强度分级）/ 建议怎么改（只从敏感性排名给方向，禁止编数字）/ 离贷款可贷还差什么（P5 后接 DSCR）。UI 上是结果页的一张"顾问解读"卡 + 刷新按钮，**绝不开放自由对话**（防幻觉、防成本失控、维持 §7 程序算铁律）。

## 5. 人工决策清单（AI 不擅自拍板，Phase 执行到对应点前持续有效）
