# 05 · 测试与验收规范

> 效力：见 [00-INDEX](./00-INDEX.md) 第 1 节 · 测试结果是**唯一被承认的完成证据**

## 1. 基线（2026-09-18 本机实测，不得下调）

| 项目 | 命令 | 基线值 | 说明 |
|---|---|---|---|

**任何改动后，上表任一项劣化即视为回归，必须修复或解释。**

---

## 2. 测试分层要求

| 层 | 要求 |
|---|---|
| **内核计算** | 每一处计算逻辑必须有单元测试；**关键算例必须有确定性快照**（逐位可复现） |
| **参数与溯源** | 参数键合法性、`confidence` 钳制、`FACT` 必须有 `sourceUrl` —— 全部要有测试 |
| **参数迁移** | 迁移前后内核输出**逐位一致**的对比测试（这是迁移的唯一验收标准） |
| **产品层** | 关键路径（L1 浏览 → L2 出报告 → 导出）必须有集成测试 |
| **AI 相关** | LLM 输出必须过 Schema 校验（宪法 §18/§20）；禁止直接信任模型返回值 |

---

## 3. 完成定义（Definition of Done）

一个任务只有同时满足以下全部，才允许汇报「完成」：

```
1. 代码已改（且改动最小化）
2. 类型检查 0 错误
3. 单元测试 ≥ 基线（1,167）
4. 若动过内核 → 快照测试通过且差异已逐一解释
5. 若动过参数 → 引用该参数的既有测试全部通过
6. 文档已更新（涉及规范/接口/数据结构）
7. CHANGELOG 已记（版本号 + 时间 + 原因 + 内容 + 效果）
8. 汇报中含真实命令输出
```

**缺任一项 → 不得说「完成」。**

## 4. 已知环境陷阱（新环境必踩，先看这里）

| 现象 | 原因 | 处理 |
|---|---|---|
| `tsc` 报 `Cannot find name 'LayoutProps'` | `LayoutProps` 是 Next.js 16 **生成**的路由类型，住在 `.next/types/`，全新克隆还没有 | 先跑 `npx next typegen` |
| 6 个集成套件在 import 阶段就崩 | `next-auth/lib/env.js` 里 `import from 'next/server'`（无扩展名目录导入），Vitest 的 ESM runner 解析不了 | 加 `test.server.deps.inline: ['next-auth']` 或配 `resolve.alias` 指向 `next/server.js`。**这是待修的既有缺陷** |
| `--reporter=basic` 报 `Failed to load custom Reporter` | 新版 Vitest 没有 `basic` reporter | 用默认 reporter |
| 集成测试需要数据库 | 依赖 `DATABASE_URL` + Neon | 无 `.env` 时应优雅跳过（当前跳不过去，见上一条） |

## 5. 禁止事项

1. **禁止跳过测试。** 不得用 `--testPathIgnorePatterns`、`it.skip`、删测试来「通过」。
2. **禁止修改测试以迁就实现。** 应改实现；若确认测试本身有误，须单独说明理由并记 CHANGELOG。
3. **禁止虚构测试结果。** 汇报必须附真实输出（宪法 §20）。
4. **禁止在测试里依赖外部网络与真实 API**（LLM 调用必须 mock）。
5. **禁止下调基线数字。** 若确因重构导致用例数变化，必须逐条说明去向。
6. **禁止为了通过快照而更新快照。** 快照变了必须先解释清楚「为什么应该变」。
