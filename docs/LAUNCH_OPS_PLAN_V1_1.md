## 1. 上线前阻塞项（BLOCKERS — 不解决就不能对真实陌生人开放）

按"对商业闭环的阻断程度"排序。每条标注【我已能推进的部分】与【只有你能定的部分】。

**B1 · 没有公网网址**（阻断：整场测试无从开始）
现状只有 `localhost:3000`，仓库无部署配置、`.env` 无 `NEXT_PUBLIC_SITE_URL`。
- 我可推进：部署 runbook、环境变量清单、部署后自查清单已写进 `DEPLOY_TEST_ENV_V1_1.md`。
- 只有你能定：授权托管账号（Vercel 等）/给发布 token、录 `AUTH_SECRET`、决定域名。**这是生产部署+密钥，创始人裁决。**

**B2 · 隐私政策 / 服务条款尚未生效**（阻断：真实收集个人信息前的合规前提）
`/privacy`、`/terms` 当前是**结构化占位草稿**，页面上明写"本页为开发阶段的结构化占位，尚未生效 / 待法务审定"。
诚实标注是对的，但**在陌生人注册、留资（含邮箱/电话）之前，必须有生效版隐私政策**，否则收集个人数据不合规、也伤信任。
- 我可推进：起草一份**纯事实性**的数据处理说明（本应用到底收集什么字段、存哪、是否用 cookie/会话、有无第三方追踪、如何删除），交你/法务定稿。
- 只有你能定：**法律最终文本属创始人/法务终稿**——我不能替你把"草稿"宣布成"生效"。

**B3 · 留资后的联系 / 收款口径未定**（阻断：标准 E/F 与"第一笔付费"）
留资表单本身能用（冒烟已证），但 `.env` 未配任何 `SUPPORT_EMAIL/WECHAT/URL`；三者全缺时页面显示"客服联系信息待配置"——那样用户根本无从联系，测出来的"是否询价/是否愿付费"不可信。
- 我可推进：把 `Lead→销售→成交` 的最小人工流程与状态定义写清（§6）；保证后台 `/admin/leads` 与状态流转可用（已冒烟验证）。
- 只有你能定：**真实对外的客服邮箱/微信、是否给报价、真实收款账户、真实定价**——本轮不做自动支付，第一笔成交走**人工收款 + 人工报价**，具体口径由你定。

**B4 · 「AI 解释此结果」按钮依赖外部模型密钥**（半阻断：一处会当场报错的功能）
界面存在该按钮，背后调 DeepSeek；`.env` 无 `DEEPSEEK_API_KEY` 时，用户点它会撞错。
- 只有你能定：要么**配 key 让它真能用**，要么**明确接受测试期该按钮会报错并如实记录**（我不建议为藏按钮去改产品——那是拿 UI 掩盖能力缺口）。这直接影响 §9 疑点 6 的证据。

> 上述四条之外，**没有发现任何代码级 P0 上线阻塞**。换句话说：B1–B4 全是"授权/法务/口径/密钥"类
> 人工决策，不是"功能没做完"。这正应了那句——不要因为缺高级功能而阻止上线。

## 4. 第一批用户测试方案（执行口径）

严格照 `docs/REAL_USER_VALIDATION_V1_1.md`：
- **样本**：每轮 **5–10 人**（本文按创始人最新口径下调到 5–10 起步，验证设计文档里的 8–12 为上限），
  覆盖 小型/中型/大型车队·投资 / 充电·能源运营 / 完全不懂的普通企业用户；至少 2 名"会掏钱或影响掏钱"的人。
- **纪律**：零培训、不解释、不提示储能在哪、不解释 NPV/IRR/两个电价、记原话、不因发现问题当场改代码、测试期冻结产品。

- **前置**：B1（公网网址）+ B3（真实客服/联系）+ B2（生效隐私政策）关闭后，才把链接投给真人。
- 产出：`docs/REAL_USER_TEST_RESULTS_V1_1.md`（样本结构、A–F 通过率、红线、P0–P3、原话、
  最关心价值、最不信任处、愿付费的东西、不愿付费的原因、是否产生真实 Lead、待修 Top3、是否二轮、是否启动融资、是否启动 AI 顾问、下一阶段建议）。

## 6. Lead → 销售 → 成交 最小流程（纯人工，先不上自动销售系统）

**访问 → 沙盘体验 → 注册 → 保存 → 留资 → 人工联系 → 试用/报价 → 成交**

- **访问/体验/留资**：产品侧已通（冒烟验证）。游客即可留资；注册后 Lead 自动归因到账号（`userId`）。
- **线索状态机（复用现有）**：`NEW 待处理 → CONTACTED 已联系 → CLOSED 已归档`。后台 `/admin/leads` 逐条可流转、可按状态筛。
  建议给"待处理"设 **SLA：24–48 小时内首次人工联系**——陌生测试用户若留了资却没人理，F 与付费意愿直接归零。
- **人工报价/交付（本轮唯一变现方式）**：不自建支付。流程为——
  ① 后台看到高质量 Lead；② 用 §3 的客服邮箱/微信人工跟进，索取其真实参数与地区；
  ③ 用沙盘（可用「展开完整参数工作台」+ 导出产业方案进人工审核队列）产出一份**带口径与"示例待核实"声明的初判**；
  ④ **报价/收款/合同由创始人人工敲定**（真实定价与收款账户＝§1 的 B3，你定，我不替你定）。
- **不做**：自动分配、自动化营销、复杂 CRM 流水线——都是"以后可能有用"，进 BACKLOG。

## 7. 上线后第一轮迭代规则

1. **只认行为证据**：改产品的依据是 §4/§5 的真实观察与 §6 的真实 Lead 结论，**不以 AI 推测驱动大型重构**（宪法口径）。
2. **优先级门**：新发现按 §（验证设计）§7 分 **P0 断链 / P1 毁信任或卡转化 / P2 摩擦 / P3 打磨或越界**；
   **只有 P0/P1 有资格立刻申请改动**，P2 攒批评审，P3 挡在门外。
3. **每轮闭环**：修完 P0/P1 → 加/跑回归 → 再测一小批真人 → 复评 A–F。**小步快跑，但按"完整业务目标"成块做**（不极端碎片化、也不跨阶段乱扩）。
4. **改动分级与停手线**（§八/§九）：
   - 普通 UI / 文案 / 引导 / 可发现性（如"储能两级才找得到""车辆数量措辞"）→ 属 P0/P1 体验修正，可自主推进并回归。
   - **模型 / 财务公式 / 电价模型 / 储能经济 / 融资 / 关键默认值 / MODEL_VERSION / 黄金样本** → **高风险**：必须完整记录
     修改原因·公式变化·影响范围·版本变化·新旧结果·回归结果，**且经你确认后才动**；绝不为"结果更好看"调模型。
   - **收费定价 / 真实收款 / 法务终稿 / 外部真实数据授权 / 数据库重大结构** → **停，等创始人**。
5. **成功只看 7 件事**（§十一）：是否真上线 / 是否有人用 / 是否留了有效联系方式 / 是否有人愿试用企业服务 / 是否有人愿付费 / 用户最需要啥 / 用户最不信啥。
   **不看**功能数 / 页面数 / 代码量 / Agent 数。
