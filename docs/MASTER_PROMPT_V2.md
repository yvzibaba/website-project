## 二、商业模式的三个层次（功能必须归属其一）

| 层 | 是什么 | 收费 |
|---|---|---|
| **L1 开放基准** | 公开测算方法论 + 区域参数库（带来源与置信度）+ 可复算算例 | **永久免费**（它是楔子，不是收入） |

| **L3 决策复核** | 针对具体标的的第三方复核与方案对比 | **项目制**（现金 + 真实案例 + 行业信任） |

**任何功能开发前必须声明它属于哪一层。归属不明者默认不开发。**

## 四、技术架构（唯一允许的形态）

```
① 产品层         src/app/**、src/components/**
                 └─ 沙盘工作台 / L1 基准浏览 / L3 复核流 / 报告导出
② 通用壳         Payload（内容与参数：存储·编辑·版本·发布）+ 现有认证
                 └─ 只管数据怎么存怎么编怎么发，绝不承载计算
③ 领域内核       kernel/**（@app/kernel）
                 └─ 零框架依赖；可以被依赖，绝不反向依赖
④ 持久层         Prisma + PostgreSQL
```

**三条边界铁律：**

1. **内核不许碰框架**（禁 `next` / `react` / 浏览器 API / `next-auth`）
2. **通用壳不许自研**（账号/权限/计费/后台/审计一律用成熟方案）
3. **Payload 只管内容，不管计算**（hook 里只许校验与审计）

细则见 [`docs/ai-rules/01-ARCHITECTURE.md`](ai-rules/01-ARCHITECTURE.md)。

> **瓶颈 100% 在数据，不在代码。** 现在去重构、换底座、美化界面，只是给一个数字不可信的引擎换壳。

### Phase 0 要做什么

**主任务：把山西包 31 个参数字段从「示例占位」抬到可引用等级。**

- 逐项找权威原文（政策文号 > 电网/运营商公告 > 统计公报 > 设备手册 > 年报）

- 判定 `evidenceKind`：有明确原文支撑具体数值才升 `FACT`，否则**维持 `ASSUMPTION`**

- 写清 `note`（口径差异、适用范围、时效边界、已知冲突）

**唯一成功范本**：`region.demandCharge 44 → 0`，依据《山西交规划发〔2026〕52号》。**把这个流程复制 31 遍。**

## 七、绝对约束（不可协商）

1. **禁止自研已被解决的问题。**
2. **禁止让内核依赖框架。**
3. **禁止把占位数据当事实输出**（`confidence≤50` / `ASSUMPTION` 不得进入对外算例与结论）。
4. **禁止编造来源。** 宁可维持 ASSUMPTION，**绝不为凑「已核实」而填链接**。
5. **禁止虚构完成 / 虚构测试通过 / 隐藏错误。**
6. **关键计算必须由程序完成**，禁止 LLM 口算（宪法 §7）。
7. **禁止未经允许删除已有功能。**
8. **改内核必须先出快照**（测试数 + 确定性输出），变动须逐条解释。
9. **不达阶段门槛不得跳阶段。** 若创始人要求跳，必须明确指出这违反宪法 §24/§33 并说明风险。
10. **禁止把 851 个内核测试用例当作「可以重写」的东西。**
