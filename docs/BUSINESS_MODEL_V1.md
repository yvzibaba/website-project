# 商业模式定稿 V1.0（光储充重卡 · 可信测算基准）

> 状态：**待创始人确认** · 定稿日期 2026-09-18
> 本文件是商业模式的**唯一权威版本**。与 `docs/MASTER_PROMPT_V1.md` 第21/42节的旧表述冲突时，**以本文件为准**（理由见第 8 节差异表）。
> 宪法修订提案见第 9 节 —— 本文件的新原则需经宪法 §29–§34 增补后生效。

---

## 1. 一句话定位

> **为光储充重卡项目提供「可被第三方引用、可复算、可溯源」的技术经济测算基准与决策工具。**

三个关键词都不能少：

| 关键词 | 含义 | 为什么必须有 |
|---|---|---|
| **可被第三方引用** | 别人能拿你的数字去和别人谈 | 这是「标准」的定义，也是唯一可守的护城河 |
| **可复算** | 任何人拿同样的参数能算出同样的结果 | 否则数字不可信，就退化成又一个拍脑袋的 Excel |
| **可溯源** | 每个参数说得清出自哪份文件、截至何时 | 这是与所有竞品的分水岭 |

**身份**：轻资产**决策服务方与项目发起方**。不建项目、不持资产、不做投资决策。

---

## 2. 要解决的行业问题

光储充重卡的单站投资在数千万级。这笔账每一方都在算：业主、EPC、投资机构、设备商、地方政府。

**但各算各的，结果互不承认。** 因为测算强依赖假设：区域峰谷价差、重卡运力与补能模式（换电 vs 超充）、电池循环寿命与衰减、土地与增容成本、并网条件、利用率。

传递链条是这样的：

```
假设不透明 → 结果不可比 → 交易成本极高
→ 融资谈不拢、EPC 不敢承诺、业主被套、投资机构不敢出手
```

**所以真正稀缺的不是数据，是「可信」。** 谁提供可信的共同语言，谁就站在这条产业链的信息枢纽上。

## 3. 客户分层（ICP）

| 层级 | 是谁 | 付费意愿 | 为什么 |
|---|---|---|---|
| **主客户** | 投资机构 / 产业基金的能源赛道分析师 | 高 | 决策错了代价数千万，最愿意为「可信」付钱 |
| **主客户** | EPC / 总包的技术商务负责人 | 高 | 报价要能站得住，否则要么丢单要么亏钱 |
| **主客户** | 设备商（换电 / 超充 / 储能）BD | 中高 | 需要向客户证明方案经济性 |
| **次客户** | 地方政府能源 / 招商部门 | 中（项目制） | 需要第三方口径做项目论证 |
| **次客户** | 业主方（物流车队、港口、矿区） | 中（项目制） | 需要判断「到底划不划算」 |
| **渠道** | 全行业从业者 | 无（免费） | 他们是标准传播者，不是收入来源 |

**注意**：主客户全是「要拿这个数字去向别人交代」的角色。这决定了产品形态 —— 输出必须**经得起追问**。

## 4. 三层产品与收费

### L1 · 开放基准层 —— 免费

内容：公开的测算方法论 + 区域参数库（带来源与置信度）+ 可复算的公开算例。

- **形态**：一份严谨的公开网页。不需要登录、不需要后台、不需要产品。
- **KPI**：**被引用次数**（唯一指标）
- **硬规则**：**永不收费**。标准的价值在于被引用，收费只会阻碍传播。

### L2 · 测算工具层 —— 订阅（★ 承重墙）

内容：私有项目沙盘 —— 输入自己的参数，跑出 CAPEX / OPEX / 收益 / 敏感性，每份结果带溯源指纹。

- **客户**：主客户
- **计价**：**席位订阅 + 活跃项目数分档**
- **定价锚点**：一份传统能源咨询报告的价格，但变成按月可续
- **为什么可持续**：项目在滚动、电价政策在变、参数要更新 —— 只要行业在动就有复购理由

### L3 · 决策复核层 —— 项目制（不追求规模）

内容：针对具体标的的第三方复核、方案对比、尽调支持。

- **客户**：投资机构、产业基金、地方政府
- **计价**：按项目，锚定尽调/咨询费的 1/5–1/3
- **它真正的价值不是收入，是三个副产品**：
  1. 真金白银的现金流
  2. 真实案例与参数沉淀（反哺 L1 与 L2）
  3. 行业信任与背书
- **关键**：**不建项目，只为别人的项目决策提供复核。** 数千万 CAPEX 风险不由我们承担。

> **记法：L1 是楔子，L2 是生意，L3 是现金。**

## 5. 核心指标

### 北极星指标

> **被引用的基准算例数量**

不是注册数、不是访问量、不是方案数。理由：整个商业模式成立的前提是「标准被引用」，这个指标消失，L2 就不存在。

### 分层指标

| 层 | 指标 |
|---|---|
| L1 | 基准算例引用数 · 参数置信度分布（S/A 级占比）· 公开算例可复算率（必须 100%） |
| L2 | 付费席位 · 活跃项目数 · 月度复算次数 · 席位留存率 |
| L3 | 复核项目数 · 由复核转出的真实投资决策数 |

### 护栏指标（不可为增长而牺牲）

1. **参数置信度分布**：S/A 级占比只能升不能降。禁止为「看起来完整」而填占位值。
2. **算例可复算率 100%**：任何一个公开算例，第三方按文档必须能算出同样结果。
3. **无来源不发布**：任何进入 L1 的参数必须有可点击核验的来源或明确标注为假设。

## 6. 冷启动路径（阶段化，带硬门槛）

**每一阶段不达门槛，不得进入下一阶段。**（落实宪法 §24「核心闭环稳定 > 功能增加」）

| 阶段 | 时间 | 做什么 | **进入下一阶段的门槛** |
|---|---|---|---|
| **0 数据做功** | 0–2 周 | 把山西包 31 个参数从占位（confidence≤50）抬到可引用等级；每项落实 source / asOf / evidenceKind | 山西包 S+A 级参数占比 ≥ 70% |
| **1 标准验证** | 2–6 周 | 以 L1 形态公开发布；找 5–10 个从业者（业主 / EPC / 投资机构分析师各若干）对话 | **至少 3 位从业者愿意在自己的工作中引用它** |
| **2 工具最小可用** | 6–12 周 | 参数入库 + 沙盘工作台 + 带溯源指纹的报告导出 | **至少 2 个付费席位** |
| **3 复核首单** | 并行推进 | 承接第一个 L3 复核项目 | 完成 1 单真实复核并交付 |
| **4 第二省** | 视阶段 1–3 结果 | 复制「单省数据功课」流程到第二个省 | **单省功课成本 / 该省可支撑收入 < 1** |

**阶段 1 是整个模式的证伪点。** 如果没有人愿意引用，L2 就没有生意，方案不成立 —— 此时应回到内容生意路线，而不是继续投入。

## 7. 明确不做（Non-goals）

| 不做 | 原因 |
|---|---|
| **案例库 / 内容电商** | 旧主线。降级为可选上游能力，不投入产品资源（详见第 8 节） |
| **六大行业并行** | 收缩为单一垂直：新能源 → 光储充重卡。一个剖透胜过六个都浅 |
| **建实体项目 / 持有资产** | CAPEX 数千万级，「个人创始人」这个前提对能源资产不成立 |
| **做投资决策** | 只做决策支持，不承担决策后果与合规责任 |
| **多省铺开** | 阶段 4 门槛验证前不扩省 |
| **多租户 / 在线计费** | 到 L2 真正有机构客户前不建。起步用简单方案 |
| **社交 / 社区 / 知识图谱 / 推荐系统 / 原生 App** | 延续宪法 §2 的清单，维持不做 |

## 8. 与旧模式的差异（明确什么被推翻）

| 项 | 旧模式 | 新模式 | 处理方式 |
|---|---|---|---|
| 主线 | 全球案例筛选 → 解构 → 本土化，产出方案包 | 光储充重卡可信测算基准 + 决策工具 | **换主线** |
| 商品 | 产业解决方案 Solution Package（34 项内容） | 可信基准（L1）+ 测算工具订阅（L2）+ 复核服务（L3） | **换商品** |
| 漏斗 | 60 → 20 → 10 → 3 → 1 每日案例漏斗 | 无每日漏斗；改为单省数据功课 + 阶段门槛 | **降级/冻结** |
| 行业 | 六大行业并行 | 单一垂直（光储充重卡） | **收缩** |
| 收入 | 低价方案 + 企业适配 + 项目服务 | L2 订阅为主，L3 项目制为辅，L1 永久免费 | **换收入结构** |

| 终局（宪法 §26） | V2 企业适配 → V3 POC → V4 项目发现… | 保持终局不变，但 V1 定义改为「L1 被引用 + L2 首批付费」 | **改 V1 定义** |

## 9. 宪法修订提案（需创始人裁决）

按宪法第 13 条与 `PROJECT_RULES.md` 的冲突裁决规则，本商业模式与现行宪法 §26（终局：V1 = 案例 + 解决方案）冲突，因此**须增补条款而非默认生效**。提案：

- **§29 商业模式分层原则**：任何功能开发前必须先声明它归属 L1（获客/标准化）、L2（收入）、L3（现金/信任）中的哪一层。无法归属者默认不开发（与 §3 一致）。
- **§30 基准可信原则**：L1 永久免费；进入 L1 的参数必须有可核验来源或明确标注为假设；公开算例的可复算率必须为 100%。
- **§31 底座与内核边界原则**：通用基础设施（账号/权限/计费/后台/审计）**必须优先采用成熟方案**，禁止自研已被解决的问题；领域内核**必须保持零框架依赖**。
- **§32 内核不可变原则**：内核（`kernel/`）的任何改动必须附快照测试结果；内核不得引入 Next.js / React / 浏览器 API 依赖。
- **§33 单省验证优先原则**：未达阶段门槛不得扩省；扩省前必须核算「单省功课成本 / 该省可支撑收入」。
- **§34 诚实成本原则**：参数置信度必须公示；禁止为「看起来完整」填充占位值；占位值不得进入对外发布的算例。

**生效记录**：已于 2026-09-18 记入 `CHANGELOG.md`（版本号 + 时间 + 原因 + 内容 + 效果），并按宪法第 13 条版本化。六条对 §1–§28 为纯增补，不改写任何既有条款。

## 10. 失效条件（诚实边界）

以下任一条成立，本模式不成立，应尽早转向：

1. **从业者不关心假设是否透明** —— 只想要一个看起来专业的数字、从不交叉核对。此时应按内容生意路线走，不应投入 L2。
2. **关键参数长期无法升档** —— 若 31 个字段里多数拿不到权威来源，引擎将永远停在「逻辑演示」。
3. **单省功课成本 > 该省可支撑收入** —— 模式不可规模化。**这是最需警惕的一条**，阶段 0/4 必须诚实核算。
4. **时间预算不允许** —— L2 出订阅收入通常需 6–12 个月；若需要更短现金回报，应优先做 L3。

**复审触发点**：阶段 1 结束时强制复审一次；此后每进入一个新阶段复审一次。
