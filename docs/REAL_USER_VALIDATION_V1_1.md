# 真实用户验证设计 V1.1（REAL_USER_VALIDATION_V1_1）

> 阶段目标：**不是写代码，而是设计一次真实用户验证。** 当前版本 v0.73.0。经济模型
> `MODEL_VERSION` / `TECH_VERSION` / `PARAMS_VERSION`、黄金样本、FACT 体系全部冻结；
> 本文档不修改任何模型、财务公式、数据库结构、不开发新功能。凡在验证中或设计自查中
> 发现的产品问题，**只登记、不顺手改**（见 §8、§9）。
>
> 一句话定位（对外统一口径，与首页逐字一致）：**新能源重卡光储充项目的投资决策软件 ——
> 3 分钟算清：投多少、几年回本、最怕什么。**

---

## 0. 这份文档要解决什么

v0.73.0 已经把三条核心链路（游客 / 登录用户 / 商业闭环）在真实 Neon 上跑通，权限、
数据污染、发布守卫、Lead 生命周期、移动端基础体验均已通过。也就是说——**代码能稳定跑**。
但"能跑"不等于"陌生人看得懂、愿意信、肯留资"。

本阶段唯一目标：**设计一场可在本周就执行的第一批真实用户测试**，用最小成本回答一个问题：

> 一个没被培训过、只拿到网址的人，能不能自己在 15 分钟内走完
> 首页 → 沙盘 → 改参数 → 看结果 → 生成报告 → 留资，
> 并在离开时**知道这产品是干什么的、信不信里面的数、下一步怎么获得企业服务**？

测试产出的是**证据**，不是代码。测试结束后按 §10 的决策规则决定下一阶段（是否进入 P5、
是否需要回来修某个 P0/P1），而不是自动进入下一阶段。

### 0.1 产品事实清单（供主持人对齐，全部取自当前真实界面文案，不得凭记忆改写）

主持人发给用户的话、观察表里点的按钮，都必须用下面这些**界面上真实存在**的词。

- **首页**：主标题"新能源重卡光储充项目的投资决策软件"，价值句"3 分钟算清：投多少、几年回本、最怕什么"，
  徽章"免费 · 无需注册 · 3 分钟出结果"。主按钮 **「免费算一个项目 →」**（直达 `/workbench`，免登录）；
  次按钮 **「先选我的企业类型」**（直达 `/enterprise`）。
- **沙盘 `/workbench`**：左侧"参数控制台"。顶部诚实声明横幅：
  *"这是决策沙盘：屏幕上每个数字都是示例条件下的推演结果。下方全部默认数值（含企业画像预设）
  均为示例参数 · 未经逐条核实……拖动任何参数，右侧的技术、经济、图表、敏感性结论都会即时联动重算。"*
- **默认示例参数（山西·需量免征主情景）**：日均服务重卡数 60 辆/日、单车均充电量 250 kWh/车·次、
  充电桩 8 台 ×360kW、光伏装机 500 kWp、储能 200kW / 400kWh、工商业综合电价 0.7 元/kWh、
  综合充电单价 0.9 元/kWh。
- **参数露出实为三层（经真实页面核查校正）**：
  - **第一层·默认落地 = 「示范项目参数模型」简化档**：只露 ~10 个核心参数（地区 + 车队 + 光伏 +
    储能 + 充电 + 电价），右侧即时联动重算。陌生人**一进来看到的就是这一档**，且这里**已含一个简化的储能项**。
  - **第二层·「展开完整参数工作台 →」按钮**：点它才切到 40 余项全量工作台（专业模式）。
  - **第三层·工作台内「展开高级参数」**：储能额定功率、储能额定容量、是否配置储能、需量电价、需用系数 Kc、
    峰谷价差、光伏年等效利用小时数、各类单位造价与运维等，藏在这一层之后。
  - 另有「未启用 · 即将支持」折叠区（并网容量、土地租金、碳价、资本金占比、贷款利率等）
    明确标注**目前不参与任何计算**——这是刻意的诚实，不是 bug。
  - ⚠️ 因此"储能"的可发现性是**分叉**的：简化档里看得见一个储能项；但**逐项细化储能（功率/容量/开关）需两级点击**
    （展开完整参数工作台 → 展开高级参数）。这既是本轮 T4 的关键观察，也是 §9 疑点 3 的准确对象。
- **右侧结果区（改参数即时重算）**：核心指标卡 **净现值 NPV、内部收益率 IRR、动态回收期、
  投资回报率 ROI、盈亏平衡充电单价**；图表（含敏感性**龙卷风图**与关键因素影响力排行）；
  风险/敏感变量结论。
- **动作按钮（沙盘内真实存在）**：**「生成动态报告」**（改任一参数整份重写，免费，无需登录）、
  「AI 解释此结果」（对当前结果的文字解读，非聊天机器人）、「导出产业方案」（买家走人工审核队列）、
  「保存 / 版本」（需登录）。
- **报告 `/workbench` 内的动态报告**：投资构成（净 CAPEX·补贴后 / 毛 CAPEX / 建设补贴抵扣 /
  首年运维 OPEX / 首年电量电费 / 首年需量电费 / 首年收入 / 计算期）、光伏自用率、绿电渗透率、
  敏感性排行、以及**口径与版本溯源**（模型版本 / 技术内核版本 / 财务内核版本 / 参数模板版本 / 报告版本）。
  报告全程带"示例参数·未经逐条核实·非真实项目结果·需专业人工确认"的声明。
- **留资 `/enterprise`**：六类企业画像卡（车队 / 充电运营商 / 园区业主 / 公交市政 / 投资人 / 通用），
  底部"想直接聊？留个联系方式"的**企业询价意向（RFQ）表单**，走 `/api/leads`；**游客亦可提交**，
  登录后自动归因到账号。文案明说"页面不收集任何企业信息，不出具诊断结论"。
- **后台 `/admin/leads`**（管理员）：留资可按状态流转 **待处理 NEW → 已联系 CONTACTED → 已归档 CLOSED**，
  可按状态筛选。

> 术语提醒（观察用，不改动）：用户口中的"车辆数量"在界面写作 **"日均服务重卡数"**；
> 用户口中的"电价"对应界面上**两个**滑块——**"工商业综合电价"（买电价/成本）**与
> **"综合充电单价"（卖电价/收入）**；"储能"在默认简化档里**看得到一个储能项**，但**逐项细化储能（功率/容量/是否配置）
> 需两级点击**（展开完整参数工作台 → 展开高级参数）。这三处正是本轮要验证的理解/操作风险点（详见 §9）。

## 1. 真实用户测试对象（五类画像）

招募 8–12 人（每类 1–3 人）即可覆盖信噪比最高的第一轮。原则：**必须是没参与过本项目的人**，
越"陌生"越能暴露理解/操作/信任问题。按决策权重从高到低：

### P-1 小型重卡车队（自有 5–30 台）
- 动机：想自己装桩、算要不要上光伏储能、能不能省电费、多久回本。
- 特点：财务语言弱，最在意"投多少、几年回本、电价能不能便宜点"；决策人往往就是老板本人。
- 招募：物流/渣土/港口短倒小型车队 owner 或车队长；行业微信群、园区熟人介绍。

### P-2 中型重卡车队（30–150 台）
- 动机：有专职能源/运营岗，要做场站扩容或光储充一体化的投资初判，要给上级或合伙人交代。
- 特点：会主动核对数字、会问口径（折现率、回收期定义）；是 NPV/IRR 语义最可能被验证的人群。
- 招募：中型物流/矿业/商砼车队的新能源或运营负责人。

### P-3 大型重卡车队 / 集团（150 台以上，有投资/融资部门）
- 动机：把光储充当资本性项目立项，关心银行/合伙人看什么指标、风险敞口在哪。
- 特点：对"贷款视角（还本付息/覆盖）"有强需求——而当前是**全投资（无杠杆）口径**，这是最可能出现
  商业价值缺口的画像；决策链长、留资门槛高。
- 招募：集团战略规划/投资部、能源项目负责人。

### P-4 充电站 / 能源运营相关人员（运营商、EPC、能源服务商）
- 动机：给不同站点选址/配置快速拉敏感性，看利用率、盈亏平衡充电单价、政策免征是否到期。
- 特点：懂参数含义、能发现"这个数对不对、口径偏不偏"；是**数据可信度**最锐利的探针。
- 招募：充电运营商运营经理、光储充 EPC 售前、能源服务商分析师。

### P-5 完全不了解项目的普通企业用户（对照组）
- 动机：无特定动机，代表"被链接转发点进来"的真实流量。
- 特点：**专门用来测"30 秒能不能看懂这是干什么的"**——这是标准 A 的守门人；若连他都看不懂，
  前面所有画像的价值传达都失败。
- 招募：与能源/投资无关的普通企业职员/管理者各 1–2 人。

> 覆盖优先级（人不够时先保）：P-5、P-1、P-2、P-4、P-3。P-5 与 P-1 各至少 1 人是硬性下限
> （一个测"看不看得懂"，一个测"用不用得起来留资"）。

## 2. 招募标准与配额

| 维度 | 要求 |
|---|---|
| 身份真实性 | 与项目零参与、零利益关系；不接受团队成员介绍来的"自己人"充数 |
| 领域相关（P-1~P-4） | 实际从事重卡运输 / 充电站 / 能源投资 / 光储充 EPC，能说出自己车或站的真实量级 |
| 对照组（P-5） | 明确不了解光储充，但具备基本办公软件阅读能力 |
| 决策角色 | 至少覆盖 1 名"会掏钱或影响掏钱"的人（老板/投资/运营负责人），用于测付费意愿 |
| 设备 | 每人指定用**日常真实设备**：P-3/P-4 优先桌面；至少安排 3 人用手机测移动端 |
| 数量 | 8–12 人；每类画像 1–3 人；P-5 ≥ 2、P-1 ≥ 2 |
| 排除 | 本行业资深顾问级专家（会被"口径细节"带偏，本轮测的是"陌生人可理解性"，留到后续） |

招募话术**不得剧透产品是干什么的**，只说"帮我们试用一个网页工具、大概 15 分钟、想听你真话"。

## 3. 15 分钟测试脚本（对每个用户逐字执行）

**总原则：零培训。** 用户只拿到网址和下面这段"最少说明"。主持人**不演示、不提示、不解释按钮含义**；
全程只观察、记录，卡住超过 45 秒且明显要放弃时才允许给一次"你可以随便点点看"级别的轻推（并记录"给了轻推"）。
出声思考法：鼓励用户"想到什么说什么"，但不诱导。

**发给用户的唯一一段话（原文照发）：**
> "这是一个网页工具，地址是 <站点网址>。你按自己的理解随便用，15 分钟左右。用的时候麻烦把脑子里
> 想到的话直接说出来（比如'我在找……''这个数我以为是……'）。我不做任何讲解，就想看没讲解时你顺不顺利。"

### 时间盒与观察节点

| 阶段 | 时长 | 让用户体验的动线 | 主持人此阶段闭眼记录的事 |
|---|---|---|---|
| T0 落地首页 | 0–2 min | 用户自行打开首页，自由看 | 30 秒时问一次"你现在觉得这是个干什么的？"（原话记进 §4-Q1）；**第一次点的是哪个按钮/链接**（Q2） |
| T1 进沙盘 | 2–3 min | 引导语（中性）："你可以往下走走看" | 用户是否自己找到并进沙盘（走「免费算一个项目」或菜单）；进沙盘第一眼看哪块 |
| T2 改**车辆数量** | 3–5 min | 中性指令："试着改改跟'车'有关的数，看会发生什么" | 用户找没找到"日均服务重卡数"；把界面上的"日均服务重卡数 60"理解成什么；改了之后哪个数字动了 |
| T3 改**电价** | 5–7 min | 中性指令："再试着改改'电价'类的数" | 用户改的是**工商业综合电价**还是**综合充电单价**？还是两个都改了？改完最关注哪个结果变（Q4/Q5） |
| T4 改**光伏 / 储能** | 7–10 min | 中性指令："光伏和储能相关的数，你也想办法改一下看看" | 光伏：用户改"光伏装机"顺不顺；储能：**默认简化档里就有一个储能项**，先观察用户是否满足于此；当用户想逐项调储能（功率/容量/关不关）时，是否自行发现需点「展开完整参数工作台」→「展开高级参数」（**两级路径**，关键操作点，记录耗时/是否放弃）；改储能后盈亏平衡单价/回收期怎么变、用户信不信 |
| T5 生成报告 | 10–12 min | 中性指令："能不能弄出一份可以给别人看的东西？" | 用户是否自己点到「生成动态报告」；看报告时先读哪块；对 NPV/IRR/回收期分别作何反应（Q6）；对"示例参数·待核实"的反应（Q7） |
| T6 下一步 / 留资 | 12–14 min | 中性问题："用完这个，如果你真想建，接下来你会怎么找这个产品背后的人？" | 用户是否自己找到「导出产业方案」/「先选我的企业类型」/`/enterprise` RFQ 表单；是否主动问价（Q8）；口头愿不愿意付费（Q9/Q10） |
| T7 收尾 | 14–15 min | 填 §5 反馈表（3 分钟自填或主持人代读） | 收表 + 补问"如果一句话吐槽，你说什么？" |

**给主持人的三条红线：**
1. 用户找不到储能滑块时，**别指给他**——"找不到"本身就是重要数据（记录耗时与是否放弃）。
2. 用户问"这个数对不对"时，**别回答对不对**——回"你先说说你凭什么信/不信它"，把判断留给他。
3. 全程不评价用户的理解（不说"其实应该这样"），避免污染反馈。

## 4. 必录观察指标（11 项，逐项对应脚本节点）

每个用户一行、11 列，主持人现场速记**用户原话**（不要转译成形容词）。

- **Q1 · 30 秒产品认知**（T0）：用户认为这产品是干什么的？——原话。判"看懂"标准：能说清
  "算一个光储充/充电桩项目值不值得投 / 几年回本"这一层，答"做能源的""管车队的""查资料网站"算**没看懂**。
- **Q2 · 第一次点击**（T0）：第一个点的元素是什么？（期望：「免费算一个项目」；点导航别处/点"先选我的企业类型"
  都如实记录，衡量价值主线的指向性）。
- **Q3 · 改得最多的参数**（T2–T4）：整场里用户反复调的是哪个滑块？（车辆数 / 电价 / 充电单价 / 光伏 / 储能 / 桩数……）。
- **Q4 · 最关注的结果**（T3–T5）：用户眼睛/嘴最先锁定的指标？（回收期 / NPV / IRR / 盈亏平衡单价 / 图表形状）。
- **Q5 · 最不信任的结果**（T5）：用户主动质疑"这数不可能吧/太乐观吧"的具体指标？——原话 + 理由。
- **Q6 · NPV / IRR / 回收期 是否理解**（T5）：分别标 懂 / 半懂 / 不懂；让用户用自己的话复述"回收期是什么意思"。
- **Q7 · 储能价值是否理解**（T4）：改储能/关掉「是否配置储能」后，用户能否说出"储能到底给项目带来什么"
  （削峰套利/需量/备用）。P-5 对照组此项通常不懂，记录即可，不当失败。
- **Q8 · "示例参数 / 待核实"是否 get 到**（T5）：用户是否注意到诚实声明？反应是
  （a）更信了（"知道是示例挺实在"）/（b）无感/（c）反而不敢信（"都是假的那我干嘛用"）。这条决定后续口径策略。
- **Q9 · 是否主动询价**（T6）：用户**未经提示**就问到"多少钱/能不能出正式方案/怎么联系你们"？是/否 + 原话。
- **Q10 · 是否愿意付费**（T6）：直接问"这个你愿意花钱吗"，记 是 / 看情况 / 否 + 金额直觉（如"几百""几千算轻的"）。
- **Q11 · 愿意为什么付费**（T6）：让用户排序最肯掏钱的东西：
  ① 一份能拿去汇报/给银行的正式报告 ② 用我自己真实数据算 ③ 有人帮我看这个数靠不靠谱 ④ 更多地区/政策数据
  ⑤ 别把示例当真的把关。—— 这是付费方向定价的一手证据。

**量化汇总（用于 §6 判定）**：每人另记 4 个秒表数——进沙盘用时、成功改到储能用时、找到报告按钮用时、
找到留资入口用时；以及是否发生过"放弃/要轻推"。

## 5. 结构化反馈表（收尾发放，**拒绝"好不好用"式空泛题**）

按六个维度分块，每块先给 1 道**打分题**（1=很差 / 5=很好，便于横向汇总），再给 1 道**开放题**抓原话。
可做成腾讯文档/纸卡，3 分钟内填完。

**① 理解问题（看得懂吗）**
- 打分：不看讲解，你能明白这网站是帮你做什么决定的吗？（1–5）
- 开放：刚才哪个词/哪句话你**看不懂或理解偏了**？请写下来。（提示：如"日均服务重卡数""NPV""需量""Kc"）

**② 操作问题（点得到吗）**
- 打分：想改的数、想看的报告，你都能顺利找到吗？（1–5）
- 开放：哪个功能你**想点但找不到**、或**点了不知道发生了什么**？（重点回忆：储能参数、报告、留资入口）

**③ 模型可信度问题（信不信这套算法）**
- 打分：它算出来的"回本年限/收益率"，你第一反应信几分？（1–5）
- 开放：你觉得它**哪里不靠谱或太乐观**？如果要让你敢用，它得先满足什么？

**④ 数据可信度问题（信不信里面的数）**
- 打分：默认这些数字（电价、造价、补贴等），你信吗？（1–5）
- 开放：看到"示例参数·未经逐条核实·需人工确认"这类提示，你的反应是？**更敢用 / 无感 / 更不敢用**？为什么？

**⑤ 商业价值问题（解决真问题了吗）**
- 打分：这工具对你**真实工作**里的决定，有多大用？（1–5）
- 开放：这次测算，有没有让你**发现一个你原本没注意的问题或变量**？是什么？（衡量"把问题问全"的价值兑现）

**⑥ 付费意愿问题（会不会掏钱）**
- 打分：若它按你现在看到的能力收费，你的付费意愿？（1–5）
- 开放：你最愿意为下面哪项付钱（可多选排序）：
  正式可汇报报告 / 用我真实数据 / 专家帮我核一遍 / 更全的地区与政策数据 / 团队协作与版本管理。

**收尾单句**：如果只能改这个产品**一处**，你最想改哪里？（每题都收原话，不收形容词）

## 6. 测试成功 / 失败标准（A–F，逐人判定，再按团队门槛汇总）

单用户层面，六个判定点：

| 代号 | 判定点 | 通过标准（单用户） |
|---|---|---|
| **A** | 30 秒知道产品用途 | Q1 能说出"算光储充/充电项目值不值得投、几年回本"这一层 |
| **B** | 5 分钟完成一次测算 | 进沙盘起 5 分钟内，成功改动 ≥1 个参数并看到结果变化，且点出「生成动态报告」 |
| **C** | 理解 ≥3 个核心结果 | NPV / IRR / 回收期 / 盈亏平衡单价 / ROI 中，能用自己话至少讲对 **3 个**（Q6） |
| **D** | 主动发现并改 ≥2 个关键参数 | **未获提示**就改了 ≥2 个来自不同含义的滑块（如"买电价 + 车辆数"或"光伏 + 储能"） |
| **E** | 知道下一步如何获得企业服务 | Q9/T6 能自己说出或找到一条联系/询价路径（导出方案 / 企业画像 / RFQ 留资表单） |
| **F** | 出现真实有效 Lead | 本轮测试**合计**至少产生 **1 条**通过后台 `/admin/leads` 可见、信息真实、非主持人代填的 RFQ |

**整轮通过门槛（决定是否算"具备真实用户测试通过"）**：

- 强判据：A、B、D 三项——**≥ 75%** 的受访用户通过；
- 中判据：C、E——**≥ 60%** 用户通过；
- F——**绝对要求**：整轮 ≥1 条真实有效 Lead（可来自任何画像，P-1/P-2/P-4 最可能贡献）；
- Q8（示例参数反应）与 Q5（最不信任结果）不设通过率门槛，但**必须全部有记录**，供 §10 决策。

**任一"红线信号"触发即判本轮不通过（哪怕比例达标）**：
- ≥2 名 P-1/P-2 用户在 T4 **完全找不到储能参数**且放弃（暴露首页"光伏储能全是滑块"的预期落空）；
- ≥2 名用户把"日均服务重卡数 60"理解成**自己车队的车辆总数**导致全程误用（Q2/Q3 连锁偏差）；
- 没有任何用户能说出"这产品下一步该怎么联系你们"（E 全线失守，商业闭环认知断裂）；
- 整轮 0 条真实 Lead（F 失守）。

## 7. 问题优先级规则（测试后给发现分级，决定修不修、何时修）

按"对转化链的伤害"而非"改动大小"排序。**本阶段只登记分级，不修。**

- **P0 · 断链**：阻断任一节点，用户根本走不完 首页→…→留资。
  例：报告按钮找不到、留资表单提交无反应、移动端沙盘参数区溢出点不到。→ 修完才能谈上线。
- **P1 · 毁信任 / 卡转化**：能走完但严重削弱信任或掐断商业闭环。
  例：改完储能数字不联动（用户当场识破"假联动"）；"示例·待核实"反而让多数用户不敢用（Q8c）；
  储能/关键参数藏在高级层导致用户以为"没有储能"（红线信号）。→ 影响能否邀请更大样本前必修。
- **P2 · 理解 / 操作摩擦**：能走完、不毁信任，但明显费劲或易误解。
  例："电价"两个滑块混淆；"车辆数量"期望落差；NPV 术语劝退 P-5。→ 记入待办，排到验证之后再批。
- **P3 · 打磨 / 范围外**：锦上添花或触碰暂缓项（AI 助手、融资模型、自动支付、第二行业、
  数据大规模真实化）。→ **本阶段一律不做**，只登记。

> 分级即裁决：只有 P0/P1 有资格在测试后立刻申请改动；P2 攒一批一起评审；P3 明确挡在当前阶段之外，
> 防止"顺手改"扩散范围。任何被归为 P0/P1 的改动，若触碰冻结模块或收费/模型口径，
> 仍须停下等创始人终裁（见项目宪法）。

## 8. 明确禁止与边界（本阶段纪律）

- **不修改**：经济模型、财务公式、`MODEL/TECH/PARAMS_VERSION`、黄金样本、FACT 体系、数据库结构。
- **不开发**：融资腿（P5）、AI 聊天机器人、自动支付、第二行业扩展、参数大规模真实化。
- **不自动进入下一阶段**：测试做完即 STOP，按 §10 由真实用户证据决定下一步。
- **不隐藏失败**：任何一条链路的失败、每一个达标的红线信号，原样进报告，不做样本裁剪。
- **不编造数据**：观察记录、Lead、反馈表全部来自真实用户当场产生；无培训、无诱导、无主持人代填 Lead。
- **不顺手改产品**：§9 登记的产品疑点仅供测试重点验证，测试结束前不动代码。

## 9. 设计阶段自查 · 待真实用户验证的产品疑点（**只登记，不修**）

以下是在编写本验证设计时、对照真实界面自查出的**理解/操作/信任风险假设**，
故意转成"让真实用户去证伪"的观察点。它们**尚未构成修改依据**，须由 §4/§5 的一手反馈确认。

1. **两个"电价"滑块易混**：界面同时有"工商业综合电价"（买电/成本）与"综合充电单价"（卖电/收入）。
   用户被要求"改电价"时到底改哪个、有没有改反——对应 Q3/T3。潜在为 P2，若引发误判结果则升 P1。
2. **"日均服务重卡数"vs 用户心智"车辆数量"**：60 是"日服务量"不是"自有车数"。
   中小车队老板很可能代入成自己的车数——对应红线信号 & §6。潜在 P1。
3. **储能"细化项"藏在两级点击之后**：首页承诺"光伏储能……全部做成滑块"。默认落地是简化示范档，里面
   **有一个储能项**（多数用户够用），但**逐项调功率/容量/开关要连点「展开完整参数工作台」→「展开高级参数」**。
   本轮验证：多少人止步于简化储能项、多少人会去找细化项、找的过程顺不顺、找不到会不会误以为"储能不能细调"——
   对应 T4 / Q2 / Q7。若"想细化却找不到"普遍则 P1（预期落空）。
4. **术语门槛（NPV/IRR/需量/Kc/绿电渗透率）**：P-1、P-5 可能读不懂——对应 §5①。潜在 P2（文案层）。
5. **全投资（无杠杆）口径 vs 大型车队/融资需求**：P-3 会问"贷款怎么看、DSCR 多少"，当前无贷款视角。
   这是**已知的产品范围**（融资腿属暂缓的 P5），本轮只验证"缺口是否真的挡住 P-3 留资"，记录，不承诺、不开发。潜在 P3/商业价值项。
6. **"AI 解释此结果"按钮的存在感**：可能被误读成"AI 客服/聊天"。本轮观察用户是否误解其性质——记录，不改文案。潜在 P3。
7. **"示例参数·未经核实"的净效应未知**：诚实是纪律要求，但对陌生人可能是加分（实在）也可能是减分（不敢用）。
   以 Q8 / §5④ 定量。这决定的是**口径呈现策略**，不是删声明。

> 说明：以上任一条**都还没有改动代码**。它们进的是"验证计划"，不是"改动清单"。改不改、怎么改、
> 优先级几，全部等真实用户证据回来再定。

## 10. 测试结束后的产品决策规则（拿证据套规则，不拍脑袋）

测试收完 8–12 份记录 + 反馈表后，按下面四步走，产出**一份测试纪要 + 下一步建议**，交创始人裁决：

**步骤 1 · 计分**：逐人打 A–F；汇总 A/B/D≥75%、C/E≥60%、F≥1 条真实 Lead 的达成情况；
统计 §9 每个疑点的证据强度（几个人中招、是否触红线）。

**步骤 2 · 定级**：把所有发现按 §7 分 P0/P1/P2/P3。

**步骤 3 · 套决策矩阵**（分支即结论，防止情绪化）：

| 证据组合 | 决策 |
|---|---|
| A/B/D 达标 **且** F 有真实有效 Lead **且** 无红线信号 | **验证通过**。产品"可被陌生人稳定体验且有商业意向"。→ 可申请邀请更大样本；是否进 P5 由创始人据此单列评估，**不自动进**。 |
| 理解/价值成立（A/B 达标），但 D/E 或某红线不达标（多为操作/信任问题） | **不进入下一功能阶段**。回到代码，把暴露出的 **P0/P1**（储能可发现性、改反电价、报告/留资断链等）**按 P6 工程闭环修复并加回归**，再测一轮。 |
| A 大面积不过（30 秒看不懂是干什么的） | **先修定位/首页价值传达，不碰模型、不碰 P5。** 属定位问题而非功能问题，改动仍限 P0/P1 文案与信息层级。 |
| Q8 多数选"更不敢用"、Q5 集中质疑模型 | **可信度/数据问题优先**，但注意：把示例参数"变成真数据"属暂缓项，须先由创始人裁决数据与口径，不得临时改模型或编 FACT。此结论进"人工决策事项"。 |
| P-3 全线因"无贷款视角"不願留资，其余画像尚可 | **记为商业价值缺口**，作为"是否值得启动 P5 融资腿"的一手论据提交；本阶段不开发，交创始人定夺。 |
| F=0（无人留资）但体验尚可 | **商业闭环未验证**。优先排查 E（留资路径可见性）与价值兑现（§5⑤），修 P0/P1 后再测；不得据"体验没报错"就宣布可上线收费。 |

**步骤 4 · 交棒**：输出一页纪要（样本构成、A–F 通过率、红线信号、P0/P1/P2/P3 清单、§9 疑点证实情况、
建议下一步 + 需创始人裁决的事项），然后 **STOP**。下一阶段是否进入 P5、要不要回头改代码，
**以真实用户测试结果为闸门，不自动推进**。
